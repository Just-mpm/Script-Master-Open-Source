## Achados priorizados

### [SUGGESTION] JSDoc do `appDrawerBackdropSx` tem exemplo com `slotProps` duplicado inválido

- **Arquivo:** `src/theme/surfaces.ts:73-76`
- **Confidence:** 100/100
- **Categoria:** Bug (documentação)
- **Problema:** O exemplo de uso no JSDoc mostra dois objetos `slotProps` separados, o que não é código JSX/TSX válido — o segundo `slotProps` sobrescreve o primeiro silenciosamente.
- **Evidência:**

```typescript
// Código inválido no JSDoc (linhas 73-76):
 * <Drawer
 *   slotProps={{ backdrop: { sx: appDrawerBackdropSx } }}
 *   slotProps={{ paper: { sx: appDrawerPaperSx } }}  // ← sobrescreve o anterior
 * >
```

- **Impacto:** Documentação enganosa. Desenvolvedor que copiar o exemplo literalmente vai produzir um Drawer sem backdrop (apenas o paper será configurado). O erro não é detectado em runtime — apenas o paper receberia o estilo, o backdrop ficaria sem customização.
- **Sugestão:** Unir em um único objeto `slotProps`:

```typescript
 * <Drawer
 *   slotProps={{
 *     backdrop: { sx: appDrawerBackdropSx },
 *     paper: { sx: appDrawerPaperSx },
 *   }}
 * >
```

### [SUGGESTION] `keepMounted` removido dos 3 Drawers sem substituição (comportamento alterado)

- **Arquivos:**
  - `src/components/app/MobileBottomNav.tsx` (antes linha ~339, agora removido)
  - `src/components/app/GuestMobileNav.tsx` (antes linha ~101, agora removido)
  - `src/components/public/PublicHeader.tsx` (antes linha ~291, agora removido)
- **Confidence:** 85/100
- **Categoria:** Bug (mudança de comportamento)
- **Problema:** Os 3 Drawers tinham `ModalProps={{ keepMounted: true }}` que foi removido sem substituição no diff da release. Antes o conteúdo do drawer permanecia montado no DOM entre aberturas/ fechamentos; agora será desmontado e remontado a cada toggle.

**Evidência (MobileBottomNav como exemplo):**

```diff
-        ModalProps={{ keepMounted: true }}
         slotProps={{
           paper: {
-            sx: {/* inline */},
+            sx: { ...appDrawerPaperSx, width: 280 },
+          },
+          backdrop: {
+            sx: appDrawerBackdropSx,
           },
         }}
```

Os outros 2 Drawers (GuestMobileNav, PublicHeader) tiveram a mesma remoção.

- **Impacto:**
  - **Perda de estado interno:** scroll position em listas e valores de input dentro dos drawers serão perdidos ao fechar/reabrir. Conteúdo atual (listas estáticas) é pouco afetado, mas futuros componentes com estado interno (inputs, abas, selects) perderão estado inesperadamente.
  - **Performance:** conteúdo leve hoje, mas remontagem custa re-renderização completa do conteúdo do drawer a cada abertura.
  - **COEP:** `keepMounted: true` mantinha o drawer montado mesmo com COEP ativo. Remover pode ser positivo para COEP (menos elementos montados com `SharedArrayBuffer`), mas não há documentação explícita desta intenção.

- **Validação anti-falso-positivo:**
  - ✅ Li o diff completo dos 3 arquivos.
  - ✅ Consultei NotebookLM MUI v9: `keepMounted` ainda existe e pode ser passado como prop direta ou via `ModalProps`.
  - ✅ Conteúdo dos drawers é leve (navegação estática) — o impacto real é baixo hoje.
  - ❌ A remoção não foi documentada em JSDoc, changelog ou comentário. É uma mudança de comportamento silenciosa.

- **Sugestão:** Se a remoção foi intencional (consistência com padrão MUI que desmonta por default), documentar a decisão no JSDoc do componente ou no AGENTS.md. Se não foi intencional, restaurar com uma das formas suportadas no MUI v9:

```tsx
// Opção A — prop direta (MUI espalha props não documentadas ao root)
<Drawer keepMounted {...}>
// Opção B — via ModalProps (recomendado, explícito)
<Drawer ModalProps={{ keepMounted: true }} {...}>
```

## O que parece saudável

- **`appDrawerBackdropSx` usa tokens:** `backgroundColor: BLACK_40` vindo de `src/theme/tokens.ts` — sem valor hardcoded `rgba(...)`.
- **Migração idiomática MUI v9:** Os 3 Drawers migraram de seletor descendente `& .MuiBackdrop-root` / ausência de backdrop para `slotProps.backdrop` — padrão oficial, mais eficiente e correto.
- **Tokenização DRY:** `drawerPaperSx` inline removido de GuestMobileNav e PublicHeader; `APP_SURFACE`, `WHITE_05`, `WHITE_015` removidos dos imports — agora centralizados em `appDrawerPaperSx`.
- **Mock factory atualizado:** `surfacesMock.ts` inclui `appDrawerBackdropSx` e `appDrawerPaperSx` — cobertura completa dos 6 exports do módulo real.
- **Testes abrangentes:** 4 testes unitários cobrem tipo, `backdropFilter`, `WebkitBackdropFilter` (Safari) e `backgroundColor` do novo helper.
- **Acessibilidade melhorada:** Os 3 Drawers ganharam `id`, `aria-controls` e `aria-expanded` nos botões de abertura — antes ausentes.
- **`zIndex` corrigido no MobileBottomNav:** O seletor `& .MuiModal-root` nunca funcionava (compartilha DOM com `Drawer-root`). Agora `zIndex: 1300` é aplicado diretamente no root — comportamento funcional pela primeira vez.
- **Bug fix no mobile:** `DeleteAccountDialog` agora é controlado localmente no `MobileBottomNav` em vez de disparar evento para Sidebar (que só existe em desktop) — antes era um bug silencioso.
- **Handlers simplificados:** `useCallback` removidos de 7 handlers no MobileBottomNav — consistente com React 19 (função simples é preferida sem `memo`).
- **Lint, typecheck e tests:** 0 erros, 2617/2617 passando.

A pré-auditoria (`docs/scan/v0.135.0-auditoria-backdrop.md`) confirma que sim. A suíte de 2617 testes passando valida a ausência de regressão.
- **Sidebar.tsx (Drawer `variant="permanent"`):** Não auditada — está fora do escopo dos 6 arquivos. A pré-auditoria documenta que ela repete inline `appDrawerPaperSx` (oportunidade DRY não explorada).
- **3 Assistant Drawers (`anchor="right"`):** Fora do escopo. Não têm `slotProps.backdrop` — decisão de design que pode ser intencional ou omissão.
- **Regressão visual:** Verificada por leitura estrutural de código (estilos equivalentes), mas não por runtime visual. O backdrop do `MobileBottomNav` mudou de seletor CSS descendente para slotProps — o efeito visual deve ser idêntico porque os valores (`blur(8px)`, `BLACK_40`) são os mesmos.
- **Firebase:** Nenhum dos 6 arquivos tem integração com Firebase — escopo não se aplica.
