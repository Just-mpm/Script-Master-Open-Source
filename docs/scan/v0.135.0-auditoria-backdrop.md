## Gaps priorizados

### GAP-01 | WARNING | Risco técnico

**Sidebar.tsx não usa `appDrawerPaperSx` — duplicação inline do helper recém-criado**

- **Confidence:** 95 (escopo completo verificado, arquivo lido por completo)
- **Descrição:** O Drawer permanente da Sidebar (linhas 138-145) repete inline `backgroundColor: APP_SURFACE`, `backgroundImage: linear-gradient(180deg, WHITE_05, WHITE_015)`, `borderRight: 1px solid APP_BORDER` — exatamente os mesmos valores do helper `appDrawerPaperSx` criado nesta release. Se `appDrawerPaperSx` for alterado no futuro, a Sidebar ficará desalinhada visualmente.
- **Evidência:** `src/components/app/Sidebar.tsx` linhas 138-145 (inline) vs `src/theme/surfaces.ts` linhas 53-57 (helper idêntico)
- **Mitigações verificadas:** A Sidebar tem `backdropFilter: 'blur(22px)'` e `height: '100dvh'` extras que não estão no helper, mas as 3 propriedades base são idênticas. O `Drawer` é `variant="permanent"`, então não usa `appDrawerBackdropSx`. Não está no escopo da release.
- **Decisão pendente:** Migrar a Sidebar para usar `{ ...appDrawerPaperSx, backdropFilter: 'blur(22px)', ... }` ou manter inline? Sugere-se migrar para evitar desalinhamento futuro e manter a centralização.

### GAP-02 | SUGGESTION | Documentação incorreta

**Exemplo JSDoc de `appDrawerBackdropSx` tem `slotProps` duplicado inválido**

- **Confidence:** 100
- **Descrição:** O JSDoc nas linhas 73-75 de `surfaces.ts` mostra:
  ```
  * slotProps={{ backdrop: { sx: appDrawerBackdropSx } }}
  * slotProps={{ paper: { sx: appDrawerPaperSx } }}
  ```
  Isso não é código JSX válido — uma prop não pode aparecer duas vezes. O correto seria um único objeto com ambas as chaves:
  ```
  * slotProps={{ backdrop: { sx: appDrawerBackdropSx }, paper: { sx: appDrawerPaperSx } }}
  ```
- **Evidência:** `src/theme/surfaces.ts` linhas 73-75
- **Mitigações verificadas:** Exemplo de documentação apenas — não afeta runtime, não é executado. Nenhum import ou código real depende disso.
- **Pergunta:** Corrigir o JSDoc?

### GAP-03 | SUGGESTION | Fora do escopo

**3 Assistant Drawers (anchor="right") não têm `slotProps.backdrop`**

- **Confidence:** 90
- **Descrição:** `AssistantSettingsPanel.tsx`, `AssistantMemoriesPanel.tsx` e `AssistantHistoryPanel.tsx` são Drawers temporários `anchor="right"` que **não definem `slotProps.backdrop`**. Enquanto os 3 Drawers de navegação agora têm backdrop blur 8px padronizado, estes 3 painéis do assistente ficam sem backdrop — o conteúdo de fundo aparece sem escurecimento quando o painel está aberto.
- **Evidência:** Os 3 arquivos em `src/features/assistant/components/` — nenhum tem `slotProps.backdrop`. Comparar com `MobileBottomNav.tsx` (linhas 343-345) que tem.
- **Mitigações verificadas:** Decisão de design pode ser intencional (painéis de conteúdo sobrepostos sem backdrop é um padrão comum, ex: Gmail sidebar). Não está no escopo da release.
- **Pergunta:** Adicionar backdrop padronizado nestes 3 painéis para consistência, ou manter sem (decisão de design documentada)?

## Cenários de borda sem resposta

1. **Sidebar.tsx — Efeito de backdrop permanente?** Drawers `variant="permanent"` não usam backdrop por definição MUI. A Sidebar tem `backdropFilter: 'blur(22px)'` no `paper` (não no backdrop slot). Isso é correto e intencional — é o efeito glass do painel lateral sempre visível. Não requer mudança.

2. **E se `searchFieldSx` for adicionado a algum dos 5 componentes dos escape hatches?** Cada escape hatch documenta explicitamente que `searchFieldSx` não é importado. O comentário serve como alerta — se o componente passar a importá-lo, o teste quebra e o desenvolvedor sabe o que fazer.
